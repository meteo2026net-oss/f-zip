# طقس المركز الوطني للأرصاد الجوية السورية — SCM Weather

واجهة طقس عربية باتجاه RTL مبنية باستخدام Flutter، وتعرض التوقعات الجوية والخرائط التفاعلية لطبقات الحرارة والرياح والهطول والضغط، باستخدام Open-Meteo وWeatherAPI.

## المتطلبات

- Flutter 3.32 أو أحدث.
- Dart 3.8 أو أحدث.
- اتصال إنترنت لجلب البيانات الخارجية.

## تهيئة منصات Android وWeb

المجلدان الموجودان حالياً في المستودع كانا غير مكتملين. لإنشاء ملفات المنصات القياسية وملفات Gradle وWrapper محلياً، شغّل أحد السكربتين من جذر المشروع:

```bash
bash tool/bootstrap_platforms.sh
```

في Windows PowerShell:

```powershell
.\tool\bootstrap_platforms.ps1
```

بعد التهيئة:

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

## بناء الإصدارات

```bash
flutter build apk --release --obfuscate --split-debug-info=build/symbols
flutter build web --release
```

## حدود البيانات الحالية

- التوقعات الجوية تصل إلى 16 يوماً من Open-Meteo. بيانات جودة الهواء مستمدة من نماذج CAMS عبر Open-Meteo وليست قياسات محطات أرضية.
- متغيرات حبوب اللقاح لدى Open-Meteo متاحة لأوروبا فقط وفي موسم اللقاح؛ لذلك قد لا تتوفر لسوريا وتظهر حينها «غير متاح».
- بيانات مواقع محطات الرصد الـ13 في الواجهة توضيحية وليست اتصالاً بمحطات MCNC الفعلية.
- تتوفر صفحة خرائط جوية تفاعلية بطبقات الحرارة والرياح والهطول والضغط، مع شريط زمني حتى 72 ساعة بحسب توافر البلاطات من WeatherAPI. هذه طبقات توقعية وليست قياسات محطات مباشرة.
- طبقات الخرائط المجانية مقدمة من WeatherAPI، ويجب الالتزام بشروط الخدمة وإظهار الإسناد داخل التطبيق. خرائط الخلفية من OpenStreetMap مع الإسناد المطلوب.
- لا توجد حالياً طبقة رادار حية أو بث تنبيهات إلى أجهزة المستخدمين.
- اسم التطبيق: طقس المركز الوطني للأرصاد الجوية السورية (SCM Weather). المبرمج: إبراهيم زينب.
- تُعرض الرؤية الأفقية من أقرب توقيت ساعي مطابق عندما يقدّمها المصدر، وتبقى غير متاحة عند غيابها.
- عند غياب بيانات جودة الهواء، يعرض التطبيق أنها غير متاحة بدلاً من اختلاق قياسات.
- مساعد الطقس الحالي قائم على قواعد محلية وليس تكاملاً مع Gemini.

## حزم البناء من GitHub Actions

عند نجاح فحوصات Pull Request، ينشر GitHub Actions حزمة باسم `mcnc-weather-build-<run_number>` لمدة 14 يوماً، وتحتوي على APK ونسخة Web ومجلدي Android وWeb اللذين ولّدهما سكربت التهيئة. افتح تشغيل CI في تبويب Actions ثم قسم Artifacts للحصول على الحزمة.

## حماية إصدار Android

يبني CI إصدار Release مع تمويه أسماء رموز Dart (`--obfuscate`) وفصل معلومات التصحيح إلى `build/symbols` وعدم تضمينها في APK المنشور. هذا يرفع صعوبة الهندسة العكسية لكنه لا يجعل APK مستحيلاً للتحليل؛ كما أن حماية الشيفرة المصدرية تتطلب ضبط صلاحيات مستودع GitHub وجعله خاصاً إذا كان ذلك مناسباً.

## إسناد البيانات

بيانات جودة الهواء: Open-Meteo / Copernicus Atmosphere Monitoring Service (CAMS). يجب إبقاء إسناد المصدر واضحاً عند نشر التطبيق أو إعادة توزيع البيانات.

## ملاحظات

لا تضع ملفات `local.properties` أو مفاتيح API أو بيانات اعتماد داخل Git. ملفات المنصات التي يولدها Flutter تختلف حسب إصدار SDK والبيئة؛ أعد تشغيل سكربت التهيئة عند الحاجة ثم راجع الفروقات قبل اعتمادها.
## الملخص التاريخي الشهري

تستخدم صفحة «ملخص الشهر الماضي» نقطة نهاية Open-Meteo Historical Weather Archive لجلب آخر 30 يوماً مكتملة (مع تأخير تشغيلي قدره خمسة أيام لتفادي عرض يوم غير مكتمل). تعرض الحرارة العظمى والصغرى والهطول والرياح اليومية. هذه القيم ناتجة عن إعادة تحليل بيانات الطقس وليست قياسات مباشرة من محطات MCNC، ولا تمثل توقعات مستقبلية للشهر.

## سلوك التحديث والمساعد المحلي

- يجلب التطبيق توقعات الطقس وجودة الهواء بالتوازي لتقليل زمن انتظار تحديث الشاشة؛ تعطل خدمة جودة الهواء لا يمنع عرض التوقعات الأساسية.
- المساعد الظاهر في الواجهة مساعد محلي قائم على قواعد بسيطة وبيانات الطقس المتاحة، وليس اتصالاً بخدمة Gemini أو نموذج ذكاء اصطناعي سحابي.
- يضيف اختبار الخدمة تغطية لاستجابات HTTP غير الناجحة وJSON غير الصالح، إضافة إلى اختبار بدء طلبي التوقعات وجودة الهواء بالتوازي.
- يحتفظ GitHub Actions بأحدث تشغيل تحقق خاص بطلب السحب، ويلغي التشغيلات الأقدم عند وصول تحديث أحدث لتجنب استهلاك موارد البناء على نسخ لم تعد هي رأس الفرع.
